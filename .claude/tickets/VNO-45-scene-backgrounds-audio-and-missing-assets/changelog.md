# VNO-45 changelog

## 2026-10-25 — scene backgrounds & audio, audio regeneration, finishing missing assets

**Branch:** `VNO-45_scene-backgrounds-audio-and-missing-assets` (from `master`)
**Commit status:** uncommitted.
**Outcome:** the Scenes stage preview now shows the scene's real background and an active CG/insert, with a playable Scene audio card for the effective music, ambience and current-beat SFX. Audio assets are regenerated with audio engines, SFX are generated by the project's audio engine by default, and the Pipeline tab reports missing files and can resume at generate to finish them.

### Changed behaviour

- **Scenes preview.** The background is `scene.backgroundId` (the same id the game builder uses), not a `bg_<placeKey>` guess. This fixes the screenshot case `bg_track_to_combe_noire` vs the existing `bg_track_to_combe_noire_afternoon`. An active CG/insert is rendered as an overlay above characters (full = cover, insert = centred) and a missing background/CG keeps its "no image yet" label.
- **Scene audio.** `ProjectDetail` now exposes scene music/ambience, per-beat picture/SFX/ambience cues and `stageMusic` (`menu` + chapter tracks). A pure `resolveSceneAudio` mirrors `emit.ts`: a cue wins over the story field, `null` is silence/stop, a scene with no own music falls back to its chapter track, a chapter with no track leaves the previous track playing, and ambience carries across scenes/chapters until explicitly stopped. The card has looping players for music/ambience and a one-shot player for the beat SFX; a missing file shows a reason instead of a broken player.
- **Audio regeneration.** SFX and ambience now use audio engines (and custom audio workflows) in the Regenerate dialog, and TTS workflows are excluded from all audio kinds. The dialog starts on a valid choice instead of a blank select. `generateAsset` accepts any audio engine for SFX (ACE-Step/YuE2/MiniMax/custom), not only `chiptune`/`custom:`.
- **SFX default.** `resolveSfxEngine` makes a missing `sound.sfxEngine` mean Chiptune Studio for a pixel/music provider, else `sound.ambienceEngine` (ACE-Step by default). `sound.sfxEngine: "none"` keeps the old import-only behaviour. Existing unlocked SFX with `engine: ""` are reconciled to the project's audio engine and generated on the next generate run (`seconds: 5`).
- **Studios.** SFX/ambience now open in Chiptune Studio (when their selected version has a song file); images still open in Pixel Studio; voice references remain upload-only.
- **Pipeline.** `missingAssets` reports all non-orphaned files with no selected file and the subset the generate step may make (excludes locked/custom, voice references, hand-made images and `sfx: none`). `suggestedStart` now returns `generate` when assets are missing and the normal next step is after generate or the pipeline is done. The Pipeline tab adds an `assets missing` pill and a Missing assets card with the ids and a "Generate missing (N)" action (`runPipeline` from `generate`).

### Deviations from the plan

- The preview's ambience was first written to reset at each chapter, per the plan text. `emit.ts` does not stop the ambience at a chapter start, so the final implementation carries ambience across chapters until an explicit stop, and `resolveSceneAudio` was refined to match the per-scene chapter-track fallback for music. The plan and tests record the corrected behaviour.
- A duplicate `tests/studio-for.test.ts` produced during delegation was removed; `tests/roundtrip-studio.test.ts` is the single exhaustive mapping test.
- No Electron GUI manual check was run in this session. The UI behavior is covered by pure helper tests (stage/audio, missing assets, suggested start) and the engine suite; the visual check on the user's projects remains for the user.
